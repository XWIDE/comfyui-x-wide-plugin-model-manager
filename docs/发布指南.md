# 发布指南 / Release Guide

以 `x-wide-plugin-model-manager` 为例，记录一次完整发布（GitHub 仓库 + Comfy Registry）。

> **发布是手动步骤。** 本仓库的 `.github/workflows/publish_action.yml` **只支持手动触发**
> （`on: workflow_dispatch:`，没有 `push` 触发器）：配好 `REGISTRY_ACCESS_TOKEN` 之后，
> 到 GitHub 的 Actions 页面点 **Run workflow** 才会发布。
> **强烈建议先在本地把插件测通（尤其是「禁用 / 恢复」这类会改文件系统的动作）再发布。**
> 想改回「push 即自动发布」，workflow 文件顶部注释里给了可直接拷回的 `push:` 片段。

## 1. 创建 GitHub 仓库

1. 打开 <https://github.com/new>；
2. **「Repository name」栏必须填 `comfyui-x-wide-plugin-model-manager`**
   （上一版曾把名字填成账号名 X-WIDE，导致所有链接 404）；
3. 不要勾选自动创建 README / .gitignore（本地已经写好了）；
4. 创建后拿到地址：`https://github.com/XWIDE/comfyui-x-wide-plugin-model-manager`。

## 2. 推送本地代码

在本包目录（`ComfyUI/custom_nodes/X-WIDE_plugin_model_manager`）里执行
（目录名以本机实际情况为准，仓库名与目录名不一致不影响运行）：

```bash
git init
git add .
git commit -m "feat: X-WIDE Plugin & Model Manager 1.1.0"
git branch -M main
git remote add origin https://github.com/XWIDE/comfyui-x-wide-plugin-model-manager.git
git push -u origin main
```

- 首次 push 会弹出「Connect to GitHub」，选 **Sign in with your browser** 完成授权；
- 如果报证书错误，可执行 `git config --global http.sslBackend openssl` 后重试；
- 推送完成后确认 `pyproject.toml` 里的 `[project.urls]` 都与真实仓库地址一致。

> **这一步不会发布到 Registry。** 按现在这份 workflow，push 只会上代码，
> 上架是第 4 步的手动动作。

## 3. 别人怎么安装

- **ComfyUI Manager** → 搜索 `X-WIDE Plugin & Model Manager`（或 Install via Git URL → 填仓库地址）；
- 或手动 `git clone` 到 `ComfyUI/custom_nodes/` 后重启；
- 页面要 **Ctrl + F5 硬刷新**，否则可能读到旧的前端缓存。

## 4. 上架 Comfy Registry（让 ComfyUI Manager 能搜到）—— **手动发布**

只有上架 Registry 之后，Manager 里才能搜到、才有缩略图（只 push GitHub 不会进 Manager）。

**方式 A：GitHub Actions 手动发布（本仓库已配置，推荐）**

`.github/workflows/publish_action.yml` 已经放好，触发方式是 **手动**
（`on: workflow_dispatch:`）。第一次用需要先在网页上填两样东西：

1. 去 <https://registry.comfy.org> 登录 → 头像 / 设置里 **API Keys** → 新建一个 publishing key，复制它；
2. 去 <https://github.com/XWIDE/comfyui-x-wide-plugin-model-manager/settings/secrets/actions>
   → **New repository secret**：
   - **Name**：`REGISTRY_ACCESS_TOKEN`
   - **Secret**：粘贴上一步的 key
   → **Add secret**；
3. **确认本地已经测试通过**，再去
   <https://github.com/XWIDE/comfyui-x-wide-plugin-model-manager/actions/workflows/publish_action.yml>
   → **Run workflow**（分支选 `main`）→ 等它变绿；
4. 验证：打开 <https://api.comfy.org/nodes/x-wide-plugin-model-manager>，
   返回 200 且 `"status":"NodeStatusActive"` 就是上架成功（没上架时是 404 `Node not found`）。

**方式 B：本地 comfy-cli 手动发布（没配 Actions 时用）**

```bash
pip install comfy-cli
comfy node login          # 浏览器登录，Publisher 选 xwide
# 在本包目录执行
comfy node publish
```

要点（上一版踩过的坑）：

- **每次发布版本号必须递增**（`pyproject.toml` 的 `version`），否则会被拒绝；
  手动发布时表现为 **Registry 返回 400**（`Version already exists` 之类），
  改了 `version` 之外的提交即使 push 上去再点 Run workflow 也一样会被拒；
- 只想推改动、**不想触发发布**时，commit message 里写 `[skip ci]` 即可跳过 CI
  （手动触发的 workflow 不受影响，它只在你去点 Run workflow 时才跑）；
- `PublisherId` 必须与登录的发布者一致（本包为 `xwide`），不一致时按提示修改；
- 若这个 PublisherId 已被占用，换一个并同步修改 `[tool.comfy] PublisherId`；
- `.comfyignore` 里排除了 `docs/`、`.github/`、`__pycache__/`，所以 README 里的图片 / 链接
  **必须写绝对地址**（本仓库已经全部改成 `raw.githubusercontent.com` / `blob/main`）；
- `.comfyignore` 还排除了运行期数据（`actions.log`、`*.jsonl`、`_*.json`、`autopilot.json`、
  `CustomNode插件顾问报告.md`）—— 本机实测这些加起来约 7 MB，而且带着本机路径，
  **绝不能打进要发给别人的插件包**；`_publish_check.py` 会检查这几条规则是否还在。
- **必须先 push 到 GitHub，Registry 才能抓到 Icon 图片**，再执行发布；
- `.gitignore` 里忽略了 `_*.json` / `*.jsonl` / `actions.log`，这些是运行期缓存与本机动作日志，
  **不要提交**（缓存文件很大，而且只对本机有意义）。

## 5. 关于插件缩略图 / 横幅

- **ComfyUI Manager 与 Registry 页面上显示的图来自 Registry，而不是仓库里随便哪张图**；
- 所以 `[tool.comfy]` 的两个字段都要写**完整 raw URL**（官方规格：
  <https://docs.comfy.org/registry/specifications>）：
  - `Icon`：**正方形**、最长边 **不超过 400×400**；本包用 320×320 的 `web/logo_xwide_icon.png` →
    `https://raw.githubusercontent.com/XWIDE/comfyui-x-wide-plugin-model-manager/main/web/logo_xwide_icon.png`
  - `Banner`：**21:9**（本包 1680×720）的 `docs/images/banner.png` →
    `https://raw.githubusercontent.com/XWIDE/comfyui-x-wide-plugin-model-manager/main/docs/images/banner.png`
- 两张图都要**先 push 到 `main` 分支**，Registry 才能抓到；
- `.comfyignore` 把 `docs/` 排除在**发布包**之外 —— 这不影响 `Banner`，因为 Registry 是去
  GitHub 的 raw 地址取图，而不是从发布包里取。

## 6. 发布后续

- 功能变化 / BUG 修复都要写进 `CHANGELOG.md`，并同步递增版本号；
- 改动了「会写文件系统的动作」（禁用 / 恢复的护栏、批量上限、确认词）时，
  `README.md` / `README.en.md` 的「安全边界」小节与 `NOTICE` 都要一并更新 ——
  使用者是先读这两处才敢点按钮的，文档落后于代码比没有文档更危险。

## 7. 迭代版本（打标签 + 发 Release）

发布新版本时，除了 push 代码，**还要打标签并在 GitHub 上发一个 Release**，
这样「Releases / 迭代版本」页面里才会显示这个版本（别人也能按版本下载 ZIP）：

```bash
git add -A
git commit -m "feat: 首版（v1.1.0）"
git push origin main
git tag -a v1.1.0 -m "X-WIDE Plugin & Model Manager v1.1.0"
git push origin v1.1.0
```

然后在 <https://github.com/XWIDE/comfyui-x-wide-plugin-model-manager/releases/new> ：

1. **Choose a tag**：选刚推上去的 `v1.1.0`（或是现打新的）；
2. **Release title**：`v1.1.0 — 首个发布版本 / First release`；
3. **Describe this release**：本仓库已经准备好了现成文案 ——
   `docs/RELEASE_NOTES_v1.1.0.md`（中文 + English 两段，横线以内的内容整段粘过来即可）；
   以后每个版本也可以照着这个文件的样子新写一份；
4. 需要上传打包 ZIP 的话，用 `git archive` 生成：
   `git archive --format=zip --prefix=comfyui-x-wide-plugin-model-manager/ -o x-wide-v1.1.0.zip v1.1.0`
   （GitHub 也会自动提供 Source code 压缩包，通常不用手动传）；
5. 点 **Publish release**。

Comfy Registry 那边**要手动同步**：本仓库的 workflow 只有 `workflow_dispatch`，
所以改了 `version` 并 push 之后，还要去 Actions 页面点一次 **Run workflow** 才会发布，
否则 Manager 里看到的还是旧版本。
